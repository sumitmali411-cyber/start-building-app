## Project Overview

A full-stack e-commerce sales flow application: an **Angular 21 frontend** + **Spring Boot 3 backend**. It guides users through a configurable multi-step sales journey: pick products → match to a bundle package → configure product characteristics → checkout with payment → order confirmation.

## Commands

### Backend (from `backend/`)
```bash
./mvnw spring-boot:run          # Start the backend (runs on :8080)
./mvnw test                      # Run all tests
./mvnw test -Dtest=ClassName     # Run a single test class
./mvnw package                   # Build JAR
```

### Frontend (from `frontend/`)
```bash
npm start                        # Serve dev server on :4200 (ng serve)
npm test                         # Run tests with vitest
npm run build                    # Production build
npm run watch                    # Build in watch mode (development)
```

Both servers must run simultaneously. The frontend proxies API calls to `http://localhost:8080/api`.

## Architecture

### Sales Flow

Three predefined flow configurations control which steps are active:
- **Standard Flow**: pick → match → config → checkout → confirmation
- **Quick Buy**: pick → checkout → confirmation (skips match/config)
- **Strict Bundle Builder**: pick → match → config → checkout → confirmation (requires match + config)

The active flow is tracked in `SalesFlowStateService` (Angular signals-based state). After product selection, the frontend calls `POST /api/flow/init` to get a **flow token** (JWT-like UUID stored in-memory on the server). This token is sent as `X-Flow-Token` header for subsequent requests like `/api/match`.

### Backend Structure (`backend/src/main/java/com/example/task_manager/`)

| Layer | Purpose |
|---|---|
| `controller/` | REST endpoints — one controller per domain (Cart, Config, Flow, Order, Payment, Product, ProductMatch) |
| `service/` | Business logic — FlowService holds sessions in-memory (ConcurrentHashMap) |
| `model/` | JPA entities + POJOs (FlowInitRequest, FlowSession) |
| `repository/` | Spring Data JPA repositories |

**Database**: H2 in-memory, seeded via `src/main/resources/data.sql` on startup. Schema auto-generated by Hibernate. H2 console available at `http://localhost:8080/h2-console` (db: `jdbc:h2:mem:ecommercedb`, user: `sa`, pass: `password`).

**Payment**: `PaymentController` supports Razorpay and Adumo. Razorpay falls back to mock mode when placeholder keys are detected. Adumo is always simulated.

### Frontend Structure (`frontend/src/app/`)

| Path | Purpose |
|---|---|
| `models/ecommerce.model.ts` | All shared TypeScript interfaces and `PREDEFINED_FLOWS` constant |
| `services/ecommerce.service.ts` | **Primary service file** — contains `SalesFlowStateService` (global state via Angular signals) and all API services (`ProductApiService`, `CartApiService`, `OrderApiService`, `PaymentApiService`, `FlowApiService`, `ConfigApiService`, `ProductMatchApiService`) |
| `services/flow/sales-flow-state.service.ts` | Duplicate of state service (separate file) — prefer the one in `ecommerce.service.ts` |
| `components/` | One folder per flow step: `product-picker`, `package-matcher`, `configuration`, `checkout`, `order-confirmation` |

**Key pattern**: All services use Angular's `signal()` + `computed()` for reactive state — no NgRx, no BehaviorSubjects. The app uses `provideZonelessChangeDetection()` (no Zone.js).

**API base URL**: Hardcoded to `http://localhost:8080/api` in `ecommerce.service.ts:7`.

### Routing (`app.routes.ts`)
```
/pick   → ProductPickerComponent
/match  → PackageMatcherComponent
/config → ConfigurationComponent
/checkout → CheckoutComponent
/order-confirmation → OrderConfirmationComponent
```

### REST API Endpoints (all prefixed `/api`)

| Method | Path | Description |
|---|---|---|
| GET | `/products` | List all products |
| GET | `/packages` | List all packages |
| POST | `/flow/init` | Init flow session, returns `{ token }` |
| GET | `/match` | Get matching packages (requires `X-Flow-Token` header) |
| GET | `/config/package/{id}` | Get product characteristics for a package |
| GET/POST/DELETE | `/cart`, `/cart/{sessionId}`, `/cart/item/{id}` | Cart CRUD |
| POST | `/orders` | Create order from cart |
| GET | `/orders/{id}` | Get order details |
| POST | `/payment/create-order` | Create Razorpay/Adumo payment order |

### Seed Data

`data.sql` seeds 8 Apple products, 4 bundles, and product characteristics (SELECT/TEXT types for storage, color, engraving, etc.). Package-product relationships are defined in `package_products` join table.
